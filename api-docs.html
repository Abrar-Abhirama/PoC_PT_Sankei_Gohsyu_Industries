Dokumentasi REST API PoC Traceability v2.0.0

Dokumentasi spesifikasi lengkap RESTful API untuk sistem Machine OK/NG Traceability PT Sankei Gohsyu Industries. Menghubungkan database antrean barcode, C# IPC Gateway, PLC Simulator (OPC UA), Keyence SR-1000 Barcode Reader, dan React Dashboard.

Base URL (Development)
http://localhost:3000
API Prefix
/api/v1
Format Data
application/json (UTF-8)
Keamanan / Auth (PoC)
Open (Local Network / Intranet)

🏭 Arsitektur & Alur Pertukaran Data

Sistem beroperasi dalam siklus tertutup (closed-loop) terotomatisasi secara end-to-end:

1
Database Antrean: Tabel barcodes menyimpan data barcode suku cadang (misal dari ERP/MES) dengan status PENDING.
2
C# IPC Gateway Polling: Program background memanggil GET /api/v1/machine-results/next-barcode. Backend mengunci antrean secara atomik via FOR UPDATE SKIP LOCKED dan mengubah status menjadi PROCESSING.
3
OPC UA Handshake ke PLC: IPC Gateway menulis barcode ke node QR_Data pada PLC Omron/Simulator dan mereset status ke IDLE.
4
Laser Marking & Scanner Keyence SR-1000: Mesin melakukan marking dan barcode reader memverifikasi keterbacaan kode (menghasilkan status final: OK atau NG).
5
Pengiriman Hasil via API: IPC Gateway mendeteksi status, lalu mengirimkan payload ke POST /api/v1/machine-results.
6
Real-Time Visualization: Backend memperbarui status record dan mencatat log audit ke tabel machine_results. Web Frontend menampilkan indikator KPI, Yield Rate, dan tabel histori.

🔄 Status Lifecycle Barcode

Setiap item barcode melewati transisi status deterministik:

1. PENDING (Menunggu) ➔ 2. PROCESSING (Diambil IPC & PLC) ➔ 3. OK (Verifikasi Sukses) atau 3. NG (Verifikasi Gagal / Reject)

⚡ Panduan Quickstart

Uji coba cepat API menggunakan cURL dari terminal Anda:

bash • Quick test flow 
# 1. Cek kesehatan server & database
curl -s http://localhost:3000/api/v1/health

# 2. Buat 10 barcode uji coba (status PENDING)
curl -X POST http://localhost:3000/api/v1/machine-results/barcodes/mock \
  -H "Content-Type: application/json" \
  -d '{"count": 10}'

# 3. Ambil barcode berikutnya untuk diproses (akan berpindah ke PROCESSING)
curl -s http://localhost:3000/api/v1/machine-results/next-barcode

# 4. Kirim hasil inspeksi OK atau NG dari mesin/IPC
curl -X POST http://localhost:3000/api/v1/machine-results \
  -H "Content-Type: application/json" \
  -d '{
    "barcodeId": 1,
    "machineId": "MACHINE-01",
    "status": "OK",
    "timestamp": "2026-09-09T06:00:00.000Z"
  }'

# 5. Cek ringkasan KPI dan Yield Rate
curl -s http://localhost:3000/api/v1/machine-results/summary

GET /api/v1/machine-results/next-barcode
Dequeue antrean barcode untuk diproses mesin (Atomic Safe)

Endpoint kunci yang dipanggil oleh C# IPC Gateway secara periodik. Mengambil 1 item barcode terlama dengan status PENDING secara atomik menggunakan klausul SQL FOR UPDATE SKIP LOCKED, dan langsung memperbarui statusnya menjadi PROCESSING. Mencegah terjadinya race condition atau duplikasi pemrosesan ketika terdapat multiple gateway.

ℹ️
Jika antrean kosong (tidak ada barcode dengan status PENDING), endpoint mengembalikan respon 200 OK dengan body null.
Response Jika Ada Item (200 OK)
JSON • HTTP 200 
{
  "id": 42,
  "barcode": "PART_R_ID20260909060000_0001"
}
Response Jika Antrean Kosong (200 OK)
JSON • HTTP 200 
null
Contoh Pemanggilan di C# (IPC Gateway)
csharp • HttpClient 
// Contoh kode C# yang digunakan pada IpcGateway/Program.cs
var response = await httpClient.GetAsync("http://localhost:3000/api/v1/machine-results/next-barcode");
if (response.IsSuccessStatusCode) {
    var raw = await response.Content.ReadAsStringAsync();
    if (!string.IsNullOrWhiteSpace(raw) && raw.Trim() != "null") {
        var item = JsonSerializer.Deserialize<BarcodeResponse>(raw);
        Console.WriteLine($"Proses Barcode: {item.Barcode} (ID: {item.Id})");
    }
}
POST /api/v1/machine-results
Ingest hasil inspeksi mesin (OK / NG) dari C# IPC Gateway

Digunakan oleh C# IPC Gateway setelah laser marking dan pembacaan barcode oleh Keyence SR-1000 selesai. Mendukung 2 alur:

  • Alur Utama (Barcode-linked): Mengirimkan barcodeId. Status record pada tabel barcodes akan diperbarui dari PROCESSING menjadi OK atau NG, sekaligus dicatat di tabel riwayat machine_results.
  • Alur Langsung / Legacy: Mengirimkan machineId tanpa barcodeId. Langsung mencatat ke tabel machine_results.
Spesifikasi Request Body (JSON)
Field Tipe Wajib Deskripsi & Aturan Validasi
status String WAJIB Harus persis bernilai "OK" atau "NG" (case-sensitive). Nilai lain akan ditolak dengan error 400.
timestamp String (ISO-8601) WAJIB Waktu verifikasi format standar ISO-8601 UTC (contoh: "2026-09-09T06:14:00Z" atau dengan millisecond).
barcodeId Integer OPSIONAL* ID primary key dari tabel barcodes. Barcode wajib berstatus PROCESSING. (*Wajib jika alur barcode diaktifkan).
machineId String OPSIONAL Identifier nama mesin inspeksi. Default bernilai "MACHINE-01" jika tidak disertakan.
Contoh Request Body (Alur C# IPC Gateway)
JSON • Request Payload 
{
  "barcodeId": 42,
  "machineId": "MACHINE-01",
  "status": "OK",
  "timestamp": "2026-09-09T06:15:22.105Z"
}
Response Berhasil (200 OK)
JSON • HTTP 200 
{
  "success": true,
  "message": "Barcode PART_R_ID20260909060000_0001 status successfully updated to OK",
  "data": {
    "id": 42,
    "barcode": "PART_R_ID20260909060000_0001",
    "status": "OK",
    "createdAt": "2026-09-09T06:00:00.000Z",
    "updatedAt": "2026-09-09T06:15:22.105Z"
  }
}
Contoh Respon Validasi Gagal (400 Bad Request)
JSON • HTTP 400 (Status Bukan PROCESSING) 
{
  "success": false,
  "error": "Cannot update barcode with status 'OK'. Only 'PROCESSING' barcodes can be updated to 'OK'."
}

⚠️ Kode Status HTTP & Penanganan Error

Standar kode respon HTTP dan struktur JSON error yang dikembalikan oleh API:

Status Code Nama Status Kondisi Terjadi Format Respon Contoh
200 OK Success Permintaan GET atau pembaruan status berhasil diproses. { "success": true, "data": ... }
201 Created Created Barcode baru atau entri hasil baru berhasil disimpan ke database. { "success": true, "data": ... }
400 Bad Request Validation Error Payload tidak lengkap, format ISO-8601 salah, status bukan OK/NG, atau barcode bukan PROCESSING. { "success": false, "error": "status is required..." }
404 Not Found Resource Not Found ID barcode tidak ditemukan dalam database atau rute endpoint salah. { "success": false, "error": "Barcode with id 99 not found" }
500 Server Error Internal Error Kesalahan server tidak terduga atau kegagalan query SQL. { "success": false, "error": "Internal server error" }
503 Service Unavailable DB Unavailable Koneksi ke instance PostgreSQL terputus pada pengecekan health. { "status": "error", "message": "Database connection error" }

🗄️ Referensi Skema Database PostgreSQL

Struktur tabel relasional yang digunakan oleh sistem backend:

sql • PostgreSQL DDL 
-- Tabel 1: Antrean dan Status Siklus Hidup Barcode
CREATE TABLE IF NOT EXISTS barcodes (
    id          SERIAL PRIMARY KEY,
    barcode     VARCHAR(255) NOT NULL,
    status      VARCHAR(20) NOT NULL DEFAULT 'PENDING' 
                CHECK (status IN ('PENDING', 'PROCESSING', 'OK', 'NG')),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_barcodes_status ON barcodes(status);

-- Tabel 2: Log Audit Riwayat Mesin (OK / NG Traceability)
CREATE TABLE IF NOT EXISTS machine_results (
    id           SERIAL PRIMARY KEY,
    machine_id   VARCHAR(50) NOT NULL,
    status       VARCHAR(10) NOT NULL CHECK (status IN ('OK', 'NG')),
    timestamp    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_machine_results_machine_id ON machine_results(machine_id);
CREATE INDEX IF NOT EXISTS idx_machine_results_status     ON machine_results(status);
CREATE INDEX IF NOT EXISTS idx_machine_results_timestamp  ON machine_results(timestamp DESC);
